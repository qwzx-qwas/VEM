# M0 Model-Agnostic Usable MCP

## Outcome

M0 delivers the first locally installable React/Vite injected-preview vertical slice in which Microsoft Edge Stable can select an intrinsic JSX element, Codex can receive bounded source evidence through MCP, a user confirmation is consumed before editing, and VEM can verify the relevant HMR result from fresh runtime evidence.

M0 is a product implementation route. It is not R9, recovery research, a superseding P0 value verdict, or a claim that prior pilots succeeded. It has no phase or decision dependency on P0 or R0–R8. Completed P0 environment, protocol, fixture, selector, source-anchor and registry outputs may be reused only with their existing tests and limitations intact.

## Ordered atomic sequence

1. `M0-T1`: freeze this route, owner priority, exact task chain, reuse boundary and prior-decision immutability proof.
2. `M0-T2`: implement coordinator ownership, private runtime discovery, one authoritative project instance and restart behavior.
3. `M0-T3`: add model-agnostic MCP STDIO initialization, revision negotiation, no-task operation and truthful static capabilities.
4. `M0-T4`: connect Vite through separate same-origin untrusted browser ingress and authenticated build-registry publication.
5. `M0-T5`: expose bounded selection/source tools and resources with compatible text and privacy evidence.
6. `M0-T6`: add server-derived consumer claims and immutable, expiring, atomic single-use confirmation.
7. `M0-T7`: prepare verification before editing with a before observation, revision barrier and bounded journal cursor.
8. `M0-T8`: correlate only relevant coordinator-observed HMR updates and replay bounded early events.
9. `M0-T9`: complete from fresh evidence with direct or transaction-matched reattachment and honest terminal states.
10. `M0-T10`: pass the positive real Edge Stable two-process walking skeleton.
11. `M0-T11`: pass restart, stale-session, unrelated-update and ambiguous-target Edge negatives.
12. `M0-T12`: package the minimal injected-preview CLI and Codex MCP configuration generator.
13. `M0-T13`: prove fresh install, first selection, verified edit, upgrade rollback and clean uninstall without production residue.

Each task is completed, tested, annotated, committed and pushed before the next task begins. Splits preserve authority boundaries: coordinator and protocol, confirmation and verification, positive and negative Edge E2E, and CLI implementation and install lifecycle remain separately reviewable.

M0-T1 completed the charter, traceability, exact task chain and zero-call immutability proof. No product runtime capability is claimed by the charter itself; M0-T2 is the first implementation task.

## Model and provider boundary

- VEM MCP behavior is independent of the caller's model identity.
- No M0 runtime configuration accepts a participant model ID.
- Provider reachability is not an MCP correctness requirement.
- M0 implementation may launch local Edge, Vite and MCP processes for its declared tests, but it does not authorize an external participant model or provider request.

## First usable boundary

Before M0-T13, individual components and internal demonstrations are not described as an installable MCP product. The usable boundary requires the full local select/source/confirm/prepare/edit/HMR/complete path, honest negative behavior, an idempotent installer, explicit Codex MCP configuration, production non-participation, rollback and clean uninstall.
