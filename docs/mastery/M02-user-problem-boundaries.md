# M02：用户问题、使命与职责边界

## 本块目标

理解 VEM 为什么存在，以及它与 Codex 各自负责什么。

## 权威来源

- `docs/DESIGN.md`：§2.1–2.3
- Contract：`CORE-BOUND-001`

## 核心内容

用户面对的是浏览器里已经渲染的对象，Codex 面对的是组件、循环、条件渲染、CSS 和运行时状态。VEM 的核心价值是把用户选中的浏览器对象转换成有界、带来源、带可信度的运行时和源码证据。

VEM 负责选择、观察、source evidence、诊断、HMR 状态和验证观察；Codex 负责读代码、制定计划、修改源码、运行测试、构造断言和审查 diff。VEM 不是文件编辑器、shell 代理，也不把临时 DOM 修改当作最终结果。

## 关键边界

- VEM 提供证据，不承诺 DOM 与源码一一对应。
- Codex 做真实源码修改，VEM 不复制文件或 shell 能力。
- 主观视觉要求在证据不足时返回 `needs-review`，而不是自动宣称完成。

## 后续验收问题

1. 如果没有 VEM，用户指着页面说“改这个”时，核心信息缺口是什么？
2. 为什么让 VEM 直接写文件会破坏当前职责边界？
3. 哪类结果只能报告候选或需要人工 review？

1.所指对象和对应的具体源代码无法对应
2.他只是沟通对象和源代码之间的mcp桥梁，具体执行交给codex
3.主观修改的说法太模糊，无法确定对应源码
## 通过标准

能够用自己的话描述 VEM 的价值，并准确划出 VEM 与 Codex 的能力边界。
